# Контрольні питання — лабораторна робота №1

1. **Що таке Git?**  
   Git — розподілена система контролю версій, яка зберігає історію змін файлів і допомагає кільком розробникам працювати над проєктом.

2. **Чим Git відрізняється від GitHub або GitLab?**  
   Git — це система контролю версій, яка працює локально та може синхронізуватися з віддаленим сховищем. GitHub і GitLab — це платформи для розміщення Git-репозиторіїв і спільної розробки.

3. **Що таке repository?**  
   Repository (репозиторій) — сховище файлів проєкту та історії їхніх змін.

4. **Що таке commit?**  
   Commit — зафіксований набір змін у репозиторії з унікальним ідентифікатором і повідомленням.

5. **Що таке branch?**  
   Branch (гілка) — окрема лінія розробки, що дає змогу створювати зміни незалежно від інших гілок.

6. **Для чого використовується HEAD?**  
   HEAD вказує на поточне розташування в історії Git — зазвичай на останній commit активної гілки.

7. **Що виконує merge?**  
   Merge об’єднує зміни з однієї гілки в іншу. Якщо зміни конфліктують, конфлікти потрібно розв’язати вручну.

8. **Для чого потрібен Pull Request?**  
   Pull Request (PR) — запит на перевірку та об’єднання змін із однієї гілки до іншої. Він допомагає проводити code review перед злиттям.

9. **Чим .NET project відрізняється від solution?**  
   Project описує одну збірку або застосунок і містить файли коду та налаштування. Solution об’єднує кілька проєктів в одну спільну структуру для розробки.

10. **Для чого використовується .csproj?**  
    Файл `.csproj` містить налаштування C#-проєкту: цільову платформу .NET, параметри компіляції, залежності та посилання на інші проєкти.

11. **Що таке project reference?**  
    Project reference — посилання одного проєкту на інший, яке дозволяє використовувати його типи та забезпечує потрібний порядок збирання.

12. **Навіщо код предметної області винесено до окремого Domain project?**  
    Це відокремлює бізнес-правила й основні моделі від інтерфейсу застосунку. Такий поділ полегшує тестування, повторне використання коду та підтримку проєкту.
